# Security and privacy

Report a suspected security or privacy issue privately to the DocTrack maintainers through their approved university contact channel. If GitHub displays **Report a vulnerability** on the repository’s Security page, you can use that private form.

Include the affected version, the expected and observed behavior, and steps to reproduce with synthetic data. Keep credentials, email codes, signed links, uploaded documents and personal data out of reports. Coordinate any testing against a hosted installation with its maintainer.

Public contributions should use synthetic data. Store deployment settings, backup locations, security findings under review and internal verification evidence in the team’s approved private workspace. If a secret was published, revoke or rotate it promptly and notify the system operator. Removing a file from the current branch leaves prior commits and copies in circulation.
