All Active {% comment %} Through `filter_url`, like the filter pills below, so a queue keeps the filters already applied. They were bare `?scope=` links: a reader with "Files created by me only" set watched 4 rows become 3 on clicking Incoming and concluded the queue had narrowed their own files, when it had replaced their filter with everybody's. Each queue is now one `scope`, computed in tracking.services.apply_scope. Incoming and Received used to be a mix of `scope` and `status`, which made them mean different things from each other: Received filtered on the record's status regardless of which office held it, so a document another office had received showed up in your Received queue. {% endcomment %} Incoming Outgoing Pending Receipt Received {% comment %} A scope, like every other pill in this row, and not `?status=IN_PROCESS`. A605c14 made this row scope-based on purpose: the mixed status pills it replaced meant different things from each other, and a status-based "Received" put documents *another* office had received into your queue, because a status says nothing about who is holding the document. SCOPE_IN_PROCESS asks the same custody question Received asks and then pins the stage, so the two are halves of one queue. {% endcomment %} In Process {% comment %} Set apart, because it is not a peer of the queues beside it — it is a modifier that composes with them. Incoming + Overdue is one click from either pill now, and both light up together; while overdue was a `scope` it replaced the queue instead of qualifying it. {% endcomment %} Overdue {% comment %} Necessary once the pills preserve state: "click All Active" used to be the way out and no longer is, because it now keeps everything else set. {% endcomment %} {% if request.GET.scope or request.GET.status or request.GET.offices or request.GET.owner or request.GET.office %} Clear filters {% endif %}
