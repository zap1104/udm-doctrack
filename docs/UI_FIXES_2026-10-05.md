# UDM DocTrack UI corrections

Date: 5 October 2026

**ONLY TRY TO FIX WHAT IS NEEDED AND DO NOT BREAK ANYTHING ELSE.**

The Claude and Gemini reviews were treated as suggestions to verify against the current source and running application. Overlapping findings were combined. These changes correct existing screens and workflows without replacing the Django, PostgreSQL, Bootstrap or HTMX stack.

## What changed

### Readable screens and predictable filters

- Tracking subjects now have enough width to be read. The Open button stays on one line, and updated dates and times occupy separate lines.
- Dashboard queue subjects have a minimum readable width. Wide and compact queue layouts expose named column headers to assistive technology.
- Table containers have accessible names, a keyboard focus outline and keyboard scrolling. On small screens, wide data stays inside its table container.
- The dashboard office selector fits at both 320 and 390 pixels. Existing light and dark themes continue to use the project's semantic colors.
- Office, month, notification, report and administration filters use visible Apply, Show, Filter or Search buttons. Changing a select with arrow keys no longer triggers an unexpected reload.
- The dashboard keeps office scope, update time, permitted visibility and the meaning of the month selector visible. Longer explanatory help remains available through the existing page guide.
- The Incoming hint identifies the office being viewed. Tracking workload wording explains that active routes and completed work awaiting filing are included.
- Repeated Open, Edit, Suspend and Reactivate actions identify the relevant record, office, user or master data item in their accessible names.

Main files: `static/css/doctrack.css`, `static/js/doctrack.js`, `templates/core/dashboard.html`, `templates/core/_action_centre_queue.html`, `templates/tracking/list.html`, and existing filter templates.

### Forms and accessibility

- Field help and error descriptions use the IDs generated for the actual Django field, including prefixed forms. Date and time each describe their own help and errors.
- Failed submissions expose a linked error summary. Keyboard focus moves to that summary, and its links focus the relevant input or the visible enhanced office picker.
- Search has a persistent label appropriate to the selected Repository or Tracking mode.
- Enhanced office pickers retain invalid state and descriptions, and their filter is named for the field being edited.
- Attachment controls have associated labels. Remark and forwarding attachment inputs on the detail page have distinct IDs while keeping the original submitted field names.
- Detail action tabs and panels have reciprocal IDs, names and selection states. Existing Bootstrap keyboard behavior is retained.
- Notification filters announce which filter is current.
- Upload instructions say the file is already saved before the metadata review step. The review button says "Save reviewed details", matching the existing behavior.

Main files: `templates/partials/_field.html`, `templates/partials/_form_errors.html`, `templates/tracking/_deadline_field.html`, `templates/tracking/detail.html`, `templates/documents/upload.html`, `templates/documents/review.html`, `templates/search/search.html`, `static/js/form-errors.js` and `templates/base.html`.

### Profile saves

The Profile Information and Notification Preferences forms now submit explicit actions. Saving one binds and saves only that form. Invalid, missing or unknown actions cannot clear the other form or create a preference record. Email verification keeps its separate endpoint, and the verified email field remains protected.

Files: `apps/accounts/views.py`, `templates/accounts/profile.html`.

### Draft editing and accurate review

- Back to Edit opens the same saved draft rather than relying on browser history.
- The edit screen restores its fields, deadline, remembered destinations and saved attachments. A successful edit preserves the draft ID, tracking number, existing files and history; new attachments are additive.
- Draft edits refresh the acting account, lock and recheck the draft, enforce its existing action permission, and record an audit entry. A real rejected attachment rolls back the saved edit, attachment metadata, history and audit changes.
- Review reconstructs the complete deadline from persisted `due_at`. Explicit times survive review and editing. A blank time means end of day; an explicitly selected 11:59 PM remains distinct from the end-of-day value.
- Invalid review submissions show the date, time and valid destinations the user actually submitted. Invalid destinations prompt correction rather than showing an unrelated lost-session warning.
- Missing remembered recipients still receive the existing warning and must be selected. Another user's draft cannot be edited, and an already sent draft cannot be changed through the edit screen.
- The detail page displays the deadline time, with an end-of-day explanation where appropriate.

Files: `apps/tracking/views.py`, `templates/tracking/create.html`, `templates/tracking/review.html`, `templates/tracking/detail.html`.

## Decisions from the external reviews

- No extra session copy of the deadline time was added. The existing persisted deadline is the source of truth and avoids stale date-only session values.
- Upload was not presented as an unsaved preview or delayed final filing. That would contradict the current storage and indexing behavior.
- Accessibility was improved through labels, descriptions, errors, keyboard behavior and responsive layout. A blanket control-size rule, new preference panels and new display modes were not added without a demonstrated need.
- Permissions, receipt attestations, custody transfers, current-batch routing, CSRF protection, signed downloads, history, print behavior and the existing theme architecture were retained. The pre-existing pending-filing dashboard link change was preserved.

The new tests cover independent profile saves, deadline round trips, submitted review summaries, same-draft editing, attachment rejection rollback, permission guards and rendered accessibility relationships.

- Live Chromium browser checks covered the dashboard, Tracking list/create/detail, profile, upload, both search modes and notifications. Dashboard reflow was checked at 320 and 390 pixels; the Tracking table was checked at desktop and phone widths. Arrow keys scroll a focused table container on the phone layout.
