# UDM DocTrack security and role audit

Audit date: 3 October 2026. Scope: the local checkout, its PostgreSQL database, installed Python dependencies, and local browser previews at the time of this security pass. This includes the earlier office-administrator boundary changes already present in the working tree. No release or push was performed during this pass. Subsequent debugging and release verification are recorded in [DEBUG_AUDIT_2026-10-03.md](DEBUG_AUDIT_2026-10-03.md).

**SAFE** below means the described repository control was inspected and exercised. It does not certify an external deployment. **NEEDS IMPROVEMENT** identifies a remaining gap or verification needed. **MISSING** means no corresponding implementation was found; an unused integration does not need a speculative endpoint.

## Account boundaries

| Account | Permitted document view | Changes | Administration |
| --- | --- | --- | --- |
| Anonymous | No application records, files, reports or exports. Public sign-in/recovery screens and a minimal health response only. | No document actions. | None. |
| VIEWER | Records permitted by office history, classification and explicit grants. Private drafts remain with their creator. | No routing, receipt, remarks, uploads, completion, sharing or metadata edits. Personal account settings and notification acknowledgements remain available. | None. |
| USER | Same document visibility rules as VIEWER. Public-to-OVPA repository records are an intentional existing policy. | Their own drafts, authorized edits to repository records owned by their current office, and tracking actions when their office has custody. Reading an old route does not grant custody. | None. |
| ADMIN | Repository records in their own office only, including classification restrictions. Tracking work originating in, held by, or actually routed through their office. An external grant does not widen this office-admin boundary. | Authorized office work, account permissions and filing approval. | Accounts and audit records within their office. No global office picker, office management, holidays, master-data management or system schedule settings. |
| SYSTEM_ADMIN | All offices. | System-wide authorized work. Workflow validity still applies, including receipt before completion. | Global settings and administration. Django raw administration additionally requires Django's active/staff flags. |
| Suspended, unknown role, unassigned non-system account | Suspended/unknown accounts are refused; an unassigned account has no document rows. | Refused. | No useful office administration scope; malformed roles cannot gain access through staff/superuser flags. |

Evidence: [role and account rules](../apps/accounts/models.py#L139), [tracking visibility](../apps/tracking/models.py#L196), [repository visibility](../apps/documents/models.py#L88), [page guards](../apps/core/mixins.py#L17), [raw admin gate](../apps/core/admin_site.py#L7), [office audit scope](../apps/core/views.py#L2679), and [role matrix tests](../tests/test_all_role_security.py).

An office administrator handling an incoming tracking record can see its routing context, including the participating offices. This is necessary to handle their office's incoming/outgoing work. It does not grant access to those offices' unrelated records or repository folders.

## Confirmed flaws fixed

| Finding | Risk before the fix | Implemented fix and evidence |
| --- | --- | --- |
| Service functions trusted cached account/record instances. | A caller could retain write rights after suspension, demotion, office transfer or a change in custody. Simultaneous actions could use the same old status. | Reload and lock the active actor and affected record within a transaction: [permissions.py](../apps/core/permissions.py#L9), [tracking services](../apps/tracking/services.py#L270), [repository services](../apps/documents/services.py#L169). Tests include stale custody, four account changes and simultaneous completion. |
| Some writers treated every role except VIEWER as staff. | Unknown or inactive roles could pass a negative role check in internal calls. | Explicit active role allowlist and assigned-office requirement: [User.is_records_staff/can_start_work](../apps/accounts/models.py#L300), [mixins](../apps/core/mixins.py#L17), and both visibility querysets. |
| Read visibility and write custody were inconsistent. | A historical recipient could act on a document now held elsewhere. A same-office user could edit a restricted repository document they could not open, or act on another user's private draft through a direct service call. | Require visibility as well as write authority; serialize transitions against current custody: [tracking permissions](../apps/tracking/models.py#L519), [repository edit permission](../apps/documents/models.py#L302), and [service guards](../apps/tracking/services.py#L329). |
| Original repository uploaders retained edit permission outside their current office. | After document ownership or the uploader's office changed, authorship could still permit adding files, editing metadata or requesting extraction in another office. | Repository write permission now requires both visibility and current owning-office membership for every non-system role. Authorship/grants retain only the existing read permission: [Document.can_user_edit](../apps/documents/models.py#L303). Tests cover stale metadata/file writes, hidden edit controls, direct edit/review/upload/extraction endpoints and delayed extraction after both kinds of transfer. |
| Lower-level filing approval lacked the wrapper's authorization. | Calling the archive service directly could bypass administrator approval. | The archive implementation itself checks approval authority: [archive_tracking_record](../apps/documents/services.py#L302). Demo/self-check calls now use an authorized administrator. |
| Administrator writes could use a role/office loaded before a concurrent account change. | An in-flight account-management request could continue under old authority or overwrite a transferred target. A system admin demoted to office admin could pass an earlier cached section check. | Lock and reload the actor for privileged writes, then lock the scoped target: [RoleRequiredMixin](../apps/core/mixins.py#L40), [administrable_users](../apps/accounts/views.py#L224). Schedule permissions use the system-role mixin; master-data POSTs recheck the section after reloading the actor: [OfficeScheduleView](../apps/core/views.py#L2722), [MasterDataEditView.post](../apps/core/views.py#L2868). Tests cover suspension, demotion and transfer after the request actor was loaded. |
| Queued extraction retained the requesting user's old authority. | A delayed job could process a file after suspension, role/office change or loss of restricted access. | Re-check current permission and consent before opening files, between files and before final save: [extraction tasks](../apps/documents/tasks.py#L19), [queued-job tests](../tests/test_queued_extraction_security.py). Authorized interoffice filing can finish local extraction without widening the administrator's repository view. Actorless maintenance jobs remain trusted internal calls. |
| New documents defaulted to external OCR consent at model/service level. | Internal calls could send scanned content externally without explicitly choosing consent. | Default false in model, upload form and extraction entry points: [document consent](../apps/documents/models.py#L177), [migration 0005](../apps/documents/migrations/0005_alter_document_allow_external_ocr.py), [extract_document_text](../apps/documents/extraction.py#L401). Existing explicit choices are preserved. |
| Tag suggestions used globally visible names/usage. | Private keywords or aggregate usage could reveal another office's documents. | Non-system accounts receive tags attached to documents they may see: [suggested_tags_for](../apps/documents/services.py#L34). Global master-data editing stays with the system administrator. |
| PDF and spreadsheet extraction work was not sufficiently bounded. | Small hostile spreadsheets could advertise enormous dimensions; large PDFs could trigger excessive processing. | Cap PDF pages/characters and XLSX rows, columns and total cells; close readers reliably and explain partial extraction: [extraction.py](../apps/documents/extraction.py#L55), [processing limits](../config/settings.py#L646), [hostile-file tests](../tests/test_extraction_limits.py). Parser isolation is still needed, as described below. |
| Repository page counts used PostgreSQL smallint. | A count above 32767, including attachment totals, could fail instead of saving the document. | Widen both page-count fields without discarding existing values: [document/file models](../apps/documents/models.py#L164), [migration 0006](../apps/documents/migrations/0006_alter_document_page_count_and_more.py), and the 40000/50000-page persistence regression. Processing limits remain separate from total page counts. |
| Structured audit records did not use the text logger's redaction. | A configured secret or credential-bearing user-agent/extra field could be persisted in an audit row. | Redact summary, actor label, user-agent and nested audit extras before insertion, preserving trusted office snapshots: [log_action](../apps/core/utils.py#L39), [redaction helpers](../apps/core/security.py#L30), [audit regression](../tests/test_security_audit.py#L34). Historical rows were not rewritten. |
| Production always trusted the forwarded HTTPS header. | A directly reachable server could accept a spoofed scheme header and skip the expected HTTPS redirect. | Trust is disabled by default and explicitly enabled for Render's proxy: [production settings](../config/settings.py#L530), [render.yaml](../render.yaml#L17), [.env.example](../.env.example). Proxy header stripping still needs deployment verification. |
| Installed urllib3 2.7.0 had three known advisories. | Storage/HTTP processing used an affected dependency. | Upgrade to 2.8.0 and raise the requirement floor: [requirements.txt](../requirements.txt#L17). Both installed-environment and requirements-resolution audits reported no known vulnerabilities after the update. See the [maintainer's 2.8.0 advisory](https://github.com/urllib3/urllib3/security/advisories/GHSA-vxq7-64xx-v4gw). |
| CDN resources had no integrity verification. | An altered CDN response could replace a trusted library in the user's browser. | Add SHA-384 integrity and anonymous cross-origin loading for Bootstrap CSS/JS and HTMX: [base.html](../templates/base.html#L20). Hashes were calculated from the pinned assets and the calculation popup was verified in the browser. |
| Notification polling used an evaluated HTMX trigger expression. | Strict production script CSP blocks that expression; enabling eval to work around it would weaken protection. | Move the visibility check into an ordinary listener and disable HTMX eval, response script execution and cross-origin requests: [browser guards](../static/js/doctrack.js#L1), [notification badge](../templates/partials/_notification_badge.html#L1), [browser security tests](../tests/js/test_browser_security.cjs). CI now runs these checks too. |
| Draft/read-only/completion controls did not describe actual authority clearly. | Users could be offered an unavailable filing option, see a misleading custody warning, or be redirected to a repository record their office admin could not open. | Show draft review/send guidance, clear read-only text, completion versus administrator filing copy, and only permitted filing controls. Keep interoffice filing actors on an accessible tracking page: [detail.html](../templates/tracking/detail.html#L184), [detail/approval views](../apps/tracking/views.py#L451). Completed routing errors now explain reopening; unreceived completion errors name the correct stage. |
| QR labels were used as regex replacement strings. | Backslashes could be interpreted as replacement groups or raise an error on a printable page. | Use a callable replacement, retain escaping, and validate malicious/backslash labels as XML: [qr_svg](../apps/core/utils.py#L314), [QR regressions](../tests/test_security_audit.py). |

## Additional controls examined

- **Sessions:** database-backed cookies, password-change session hash updates, mandatory first-password-change enforcement, role-specific idle expiry, and authenticated no-store responses. Polling does not keep an unattended account active: [middleware](../apps/core/middleware.py#L98), [account views](../apps/accounts/views.py#L141).
- **IDOR:** direct record/detail/edit/file/status/print URLs use the visible querysets or resource permissions; authorized access is checked in addition to a download signature. Notification reads and document search clicks resolve through scoped rows: [document views](../apps/documents/views.py#L42), [tracking views](../apps/tracking/views.py#L60), [notification reads](../apps/core/views.py#L2334), [search clicks](../apps/search/views.py#L226).
- **CSRF:** middleware is enabled; no `csrf_exempt` application view was found. Regression requests without CSRF cover document lifecycle, sharing, uploads, profile/account settings and notifications. State-changing methods are POST rather than mutation links.
- **CSV formula injection:** exported cells starting with spreadsheet formula characters are quoted as text: [_csv_cell](../apps/core/views.py#L2437).
- **Regular-expression denial of service:** administrator-defined tag patterns use the `regex` engine with a 50 ms timeout: [_rule_matches](../apps/documents/suggestions.py#L308).
- **Audit office transfers:** server-owned actor/target office snapshots prevent history from moving into a different office's administrative view after an account/record transfer. Legacy entries without trustworthy snapshots remain visible only to SYSTEM_ADMIN. Application/model immutability is not equivalent to a database append-only privilege policy.
- **Health endpoint:** anonymous and non-system accounts receive a minimal availability response rather than counts/storage/configuration detail: [HealthzView](../apps/core/views.py#L2204).

## Scanner findings and limits

Bandit reported **18 findings: 0 high, 3 medium and 15 low**. It does not have a clean exit status, and its warnings were not suppressed.

The medium findings were two warnings for the same `mark_safe` QR return and one warning for `urllib.request.urlopen`. The QR value consists of escaped labels and library-generated SVG; malicious/backslash label tests verify the relevant boundary. The OCR call accepts a server-configured HTTPS URL without embedded credentials, not a user-supplied URL. This does not replace trusted endpoint configuration or network egress controls.

Low findings cover the guarded public demo-password literals, the rejected development key literal, demo-only pseudo-random fixture generation, non-password strings such as `all`/`False`, an old data-migration assertion, and intentional cursor-restoration/broken-page fallbacks. The demo commands and deployment checks were inspected; do not enable demo defaults on a real deployment.

The read-only database probe confirmed that the **local** runtime role is not a superuser and does not bypass RLS, but it **can create databases**. That privilege supports local isolated tests and must not be assumed suitable for production. Runtime database roles, object-storage bucket policy/IAM, TLS/proxy header stripping, real mail delivery, backups and cloud log retention remain unverified outside this repository. The tracked-file scan did not exhaust Git history, binary files, ignored files or arbitrary unknown secret formats.

## Prioritized remaining checklist

### CRITICAL

- No confirmed unresolved critical application flaw in the reviewed code. Before a real release, verify the actual deployment passes its checks, uses unique credentials, disables debug/demo tools and has private file storage. Treat any discovered leaked real key as an incident requiring rotation.

### HIGH

- Add private quarantine and antivirus/content scanning, with bounded isolated document parsing. Page/cell caps do not bound decompression or every parser's memory use. Preserve existing internal-office formats while introducing a reviewed quarantine workflow. [OWASP upload guidance](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html).
- Add MFA or a university identity provider for administrator accounts. No MFA implementation was found in the current authentication routes/dependencies. Require it first for SYSTEM_ADMIN; preserve recovery procedures and test migration from existing accounts. [OWASP authentication guidance](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html).
- Verify deployed TLS, trusted proxy header handling, bucket/container privacy, narrow storage credentials and recovery-tested backups. These are verification gaps, not claims that a particular deployed service is exposed.

### MEDIUM

- Use separate migration/test and production runtime database roles; runtime should not have CREATEDB, superuser or BYPASSRLS. Plan database row policies and audit append-only privileges with explicit worker/request context.
- Add request/body/download/search quotas at the deployment boundary. The subsequent debugging pass registers expired rate-limit cleanup through `ensure_schedules`; verify that the command and worker are active in the deployed environment. Avoid IP-only limits that punish a university's shared network.
- Review compatible dependency updates and automate both Python and pinned frontend advisory checks. Keep Django 5 and the current CSP/axes configuration compatible.
- Tighten the inline-style CSP allowance when dynamic badge/chart styling has been moved to approved classes or another compatible policy. Keep script eval disabled.
- Inspect historical/cloud/provider logs and secret history with access-controlled tooling. Current redaction does not retroactively sanitize already stored rows.

### LOW

- Replace deprecated `CheckConstraint.check` arguments during routine maintenance and retain the migrated role invariant without depending on Python assertions.
- Repeat critical navigation, dialogs, keyboard access and table scrolling on physical phones and additional browser engines.
- Keep the role matrix and negative permission cases mandatory in CI whenever new endpoints or account roles are added.

The request/worker checks follow the principle of validating authorization for each operation. Proxy scheme trust must be enabled only for a verified proxy that strips and sets the header: [Django proxy settings](https://docs.djangoproject.com/en/5.2/ref/settings/#secure-proxy-ssl-header).
