## Confirmed and repaired

| Finding | Reproduction | Repair and evidence |
| --- | --- | --- |
| Old account security credentials could become valid again | Change and then restore a security attribute. An earlier OTP session, pending challenge or verification invitation could match the restored account fingerprint. | A monotonic revision is part of the fingerprint. Model and queryset changes update it under database concurrency controls. The initial reproduction failed 18 cases. The subsequent focused group passed 156, including 94 new cases. |
| Queued extraction could read a different store's file | Configure another storage identity with the same key. A queued source or legacy job could resolve the new bytes. | Check the storage identity before opening the file when that identity was recorded. Preserve prior usable text on failure. Six new tests exercise both collections and both processing paths. |
| XLSX extraction could omit real cells | Change or remove the optional sheet dimension metadata while keeping real cells outside the declared range. | Stream actual cell extents within the existing archive limit and report truncation. Seven new tests check inaccurate metadata, saved values and coverage. The independent review identified a 16 MiB compatibility regression in the initial implementation. The final regression verifies that a larger worksheet part and a later sheet both retain their text. |
| Office file preview declaration and error handling had gaps | A DTD in UTF-16 bypassed the DOCX byte scan. An unknown DOCX XML encoding, unsupported DOCX or XLSX ZIP compression method or overly nested DOCX XML raised an uncaught exception. | Reject DOCX DTDs after decoding and normalize the reproduced malformed inputs to the existing invalid-preview responses. Eight focused tests cover both UTF-16 byte orders, valid documents, failure responses, cache headers and unchanged original bytes. |
| Clean installs could lack workbook XML protection | Removing openpyxl's optional XML protection allowed a worksheet declaration to affect a displayed value. The protection was already present indirectly in the audit environment. | Declare `defusedxml` directly, as described in the [openpyxl security guidance](https://openpyxl.readthedocs.io/en/stable/#security). The signed-in regression verifies the safe fallback and confirms the original download remains byte-identical. |
| Node test runtime pinned before the November 11 security release | `.node-version` selected 24.22.1. The [Node.js 24.22.3 release](https://nodejs.org/en/blog/release/v24.22.3) includes new security fixes in the same LTS line. | Updated the pin. Verified the downloaded executable against the upstream checksum and ran all 194 JavaScript tests with it. Node is used by the test tooling. Django serves the application. |

## Independent expectations and coverage

- The new logic module defines expected External record IDs and stage buckets independently of production list/report code. Its 85 cases include 36 External list, report and CSV comparisons, 48 calendar/interval comparisons, and a complete custody trace. A previously skipped Incoming probe now has an actual authorized Incoming fixture.
- The operator tests cover repeatable maintenance, scoped reindex and training/evaluation, dry runs and authorized recovery on synthetic records. The isolated workflow self-check covered 21 cases and the smoke check requested 256 pages as four roles. Expected permission refusals were included.
- The discovery inventory includes 322 resolved routes (204 generated by native admin), 62 forms, 56 query keys, 102 service actions, 11 jobs, two action dispatchers and 22 project commands. It records candidate test references and coverage status separately from test outcomes. Regenerate it with `python scripts/audit_inventory.py --output .vercel/security-logic-20261108/inventory`. It refuses database connections. Generated-route discovery does not imply that each action was executed under every role.
- Independent reviewers examined the monotonic account revision, storage binding, workbook extent scan and preview parser. Their compatibility findings about large worksheets and single-pass `update_fields` input were reproduced and repaired. One remaining framework edge case concerns nullable `QuerySet.update()` expressions that compute SQL `NULL`: the value change still invalidates the fingerprint, and restoring the non-null value increments the revision. The reviewer found no credential resurrection in that path. It is not used by current app workflows.
